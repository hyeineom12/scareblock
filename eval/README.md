# 평가 하니스

#14의 **E1 — lookahead 시간별 성능 곡선**을 내기 위한 오프라인 파이프라인이다.
논문(09.16)의 실험 절이 이 출력 하나로 채워진다.

브라우저가 아니라 파이썬으로 둔 이유는 실험을 수십 번 돌려야 하기 때문이다.
PoC(`poc/delay-playback.js`)는 데모·계측용이고, 여기는 평가용이다.

## 무엇을 재는가

**적시성** — 탐지가 맞았는지가 아니라 **사용자에게 도달하기 전에 개입이 준비됐는지**다.

사건마다 **탐지 지연**을 기록하고, lookahead `L`을 쓸어가며 `지연 ≤ L`인 비율을 센다.

```
지연 = (규칙이 확신에 이른 시각) − (라벨 onset) + (블러 렌더링 시간)
```

**기준점은 라벨 onset이다.** 탐지기가 되짚어 만든 추정 onset을 쓰면 탐지기를 자기
자신과 비교하게 되고, 지연이 "되짚기가 멈춘 거리"로 바뀐다(#19 리뷰 🔴1).
사용자가 노출되는 시점은 라벨 onset이다.

**확신 시각은 분석 창의 끝이다**(`Features.t_ready`). 창 시작을 쓰면 25 ms 창 안의
자극을 창이 시작할 때 이미 알았다는 뜻이 되어 지연이 음수로 나온다.

**렌더링 시간은 상수 하나**다(`evaluate.RENDER_S`, `--render-s`). M1 실측 뒤 값만
넣으면 표가 다시 나온다. 측정 전이므로 기본값은 0이다.

> **lookahead 0에서 적시성이 무너지면 「지연이 필요하다」가 증명된다.**
> 곡선이 1초 근처에서 평평해지면 3초는 과잉이라는 뜻이고,
> 그때는 **"필요한 양은 3초가 아니라 X초"** 로 쓴다 — 그쪽이 더 강한 결과다.

## 입력

**라벨** — `docs/labeling-guide.md` §1 스키마 CSV를 그대로 읽는다.

```csv
video_id,clip_id,clip_offset,onset,offset,category,ambiguous,annotator,note
aqz-KE-bpKQ,c007,742.0,46.33,47.10,jumpscare,false,B,문 쾅 + 화면 컷
```

`note`는 있으면 읽고 없으면 무시한다. `duration`은 받지 않고 `offset − onset`으로 계산한다.

**평가 분모는 라벨이 아니라 클립 목록이다.** 대조 클립은 사건이 없는 것이 정상이라
라벨 행을 하나도 남기지 않는다. 라벨에서 클립 목록을 역산하면 **대조 클립이 평가에서
통째로 빠지고 오탐이 한 건도 세지지 않는다**(#19 리뷰 🔴1). `--clips clips.csv`로
명세를 주면 그것이 분모가 되고, 없으면 wav 디렉터리 전체를 쓴다.

```
--clips 없음   라벨 있는 클립만 → precision 1.000 (대조 클립의 오탐이 안 보임)
--clips 있음   명세 전체       → precision 0.625 (오탐 3건이 세짐)
```

`clip_id` 열만 요구하고 나머지 열은 무시한다 — 명세가 열을 늘려도 안 깨진다.

**주석자는 한 명만 쓴다.** 이중 라벨링(`labeling-guide` §6) CSV를 그대로 넣으면 같은
사건이 두 번 세지고, 매칭이 1:1이라 둘 중 하나가 자동으로 미탐이 된다(#19 리뷰 🔴2).
섞여 있으면 가장 많이 단 사람을 골라 알리고, `--annotator`로 바꾼다.
**두 주석자를 함께 읽는 것은 κ 계산뿐이다.**

**클립 경계를 넘어 매칭하지 않는다.** 모든 클립의 시간축이 0에서 시작하므로 합쳐서
매칭하면 클립 A의 탐지가 클립 B의 라벨에 붙어 TP가 부푼다(#19 리뷰 🔴2).
`Detection.clip_id`를 매칭 조건에 넣어 막는다.

**오디오** — `<clip_id>.wav` 파일들이 든 디렉터리. mp4에서 뽑으려면:

```bash
ffmpeg -i c007.mp4 -ac 1 -ar 16000 -vn c007.wav
```

## 실행

```bash
pip install -r eval/requirements.txt
python3 -m eval.e1 --labels labels.csv --audio _local/wav --clips _local/clips/clips.csv
```

기울기 조건을 켜려면 `--drms-min 값`. 기본값 0은 조건을 끈 상태다.
M1 실측 뒤 렌더링 시간을 반영하려면 `--render-s 값`.

**데이터 없이 파이프라인만 점검:**

```bash
python3 -m eval.e1 --selftest
```

## 자체 점검 결과 (2026.09.12, 합성 오디오 클립 2개 × 30초)

| lookahead | 적시성 | precision | recall |
|---|---|---|---|
| 0.0s | **0.000** | 1.000 | 1.000 |
| 0.5s | **1.000** | 1.000 | 1.000 |
| 3.0s | **1.000** | 1.000 | 1.000 |

2 ms 상승 점프 스케어 5건을 모두 잡고, **1.5초에 걸쳐 서서히 커지는 크레셴도는 잡지 않았다**
(`labeling-guide` §5의 「넣지 않는 것」과 일치). 라벨 onset 기준 지연은 다섯 건 모두 0.005초
— 분석 창 25 ms의 절반 수준으로, 사실상 **한 창 안에서 확신했다**는 뜻이다.

클립을 2개로 둔 이유는 **클립 간 교차 매칭이 단일 클립에서는 드러나지 않기** 때문이다.
`c001@12.0`과 `c002@12.4`를 일부러 허용오차(±0.5초) 안에 배치했고, 자체 점검이
"다른 클립·0.05초 차 쌍은 0건, `clip_id`를 무시하면 1건"을 함께 검사한다.

**합성 데이터라 이상적인 값이다.** 실제 영상은 바닥 소음이 있고 상승이 완만해
지연이 더 길게 나온다. 이 표는 파이프라인이 도는지를 보인 것이지 결과가 아니다.
**「0.5초면 충분하다」는 이 표로 말할 수 없다** — 지연이 창 하나 크기라 0.5초든 3초든
전부 1.000이다. 실제 클립에서만 갈린다.

## 검사

라벨을 읽을 때 규약 위반을 함께 본다.

- 알 수 없는 `category`, `offset ≤ onset`
- **§2 병합 규칙 위반** — 같은 클립·카테고리에서 1.5초 안에 붙은 두 건
- **§4 대조 클립 30% 미만** — 정밀도 수치를 방어할 수 없다는 경고

## 모듈

| 파일 | 역할 |
|---|---|
| `labels.py` | §1 스키마 로드·검증, 대조 클립 비율 |
| `features.py` | RMS · **dRMS/dt** · 스펙트럼 플럭스 · 직전 정적 · 감쇠 최댓값 |
| `detect.py` | 규칙 탐지기. 확신 시각·onset 추정·`clip_id`를 기록한다 |
| `evaluate.py` | 같은 클립 안 onset ±0.5초 매칭(§6), P/R/F1 + 적시성 |
| `e1.py` | lookahead 스윕, 표 출력, 자체 점검 |

**홉은 10 ms다.** PoC의 50 ms로는 놀람 반사 문헌이 말하는 2~100 ms 상승 시간을
분해할 수 없었다(`poc/README.md` 탐지 절).

**onset 되짚기에는 1초 상한이 있다**(`Params.backtrack_max_s`). 바닥이 조용해지지 않는
구간에서는 `t=0`까지 내려가 추정이 무의미해진다(#19 리뷰 🟡3). 상한에 걸린 건수를
리포트 머리줄에 낸다 — 되짚기가 실패하는 빈도 자체가 데이터 특성을 알려준다.
되짚은 onset은 **진단용**이고 적시성 계산에는 들어가지 않는다.

**정규화는 dtype 범위로 한다.** 클립의 실제 최댓값으로 나누면 조용한 클립일수록 크게
증폭돼, 절대값인 `silence_floor`가 클립마다 다른 음압을 가리킨다(#19 리뷰 🟡5).

**`dRMS/dt`는 후방차분이다.** `np.gradient`는 중심차분이라 `drms[i]`가 `rms[i+1]`에
의존하는데, 확신 시각은 `t_ready(i)`로 적힌다 — **아직 나오지 않은 프레임으로 확신했다고
기록**하는 셈이다(#19 리뷰 🟡3). 창 시작/끝 문제와 같은 종류다.

**겹치는 라벨은 검사에서 걸린다.** 병합 검사의 하한이 0이면 겹치거나 완전히 똑같은 두 행이
그냥 통과한다(#19 리뷰 🟡4). 다만 검사는 **주석자별로** 본다 — 이중 라벨링에서 두 사람이
같은 사건을 각자 찍는 것은 위반이 아니다.

**임계값은 나머지 전부 상대값이다** — 최근 최댓값 대비로 잡아 볼륨 설정에 종속되지 않게 했다.
PoC에서 절대 임계값이 볼륨 슬라이더에 종속됐던 문제(#5 리뷰 🟡3)를 같은 방식으로 피한다.
