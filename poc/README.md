# 00단계 PoC — 3초 지연 재생

`delay-playback.js`를 유튜브 영상 페이지 콘솔에 붙여넣으면 영상이 3초 늦게 재생되고,
그 사이 지연 전 오디오에서 갑툭튀 후보를 찾아 사용자 도달 전에 블러가 걸린다.

## 실행

1. Chrome에서 유튜브 **일반 업로드 영상**을 연다 (영화·대여는 EULA·DRM으로 막힌다 — 범위 선언 참고)
2. `⌥⌘J`로 콘솔을 연다
3. **처음이면 콘솔에 `allow pasting`을 먼저 입력한다** — Chrome이 self-XSS 방지로 붙여넣기를 막는다
4. `delay-playback.js` 전체를 붙여넣는다

```
scareblockDemo.stop()          원복
scareblockDemo.blurNow(1.5)    수동 블러 — 지금 소리 나는 장면을 도달 전에 가린다
scareblockDemo.stats()         버퍼·탐지 상태
```

Safari는 쓰지 않는다. 최종 산출물이 Chrome MV3 확장이라 검증 환경을 맞춘다.

## 실측 (2026-09-08, Big Buck Bunny 60fps)

| 항목 | 결과 |
|---|---|
| `drawImage(video)` | 오류 없음 |
| `canvas.toDataURL()` | **성공 — taint 없음.** 픽셀 접근 전제 확인 |
| 링버퍼 적재 | 4.5초에 64/70 슬롯 |
| 조회된 프레임의 지연 | **3.02초** (목표 3.00초) |
| 프레임 내용 | 231/231 샘플이 비검정 — 실제 화면이 들어옴 |
| `createMediaElementSource` | 예외 없음, `AudioContext.state = running` |
| 지연 전 RMS | 25/25 샘플이 0이 아님 (0.0039 ~ 0.0731). **오디오 접근 전제 확인** |

유튜브가 MSE(`blob:`)로 미디어를 붙이기 때문에 cross-origin taint가 걸리지 않는다는
README 「기술 전제」의 근거가 추론이 아니라 실측으로 확인됐다.

**화면 표시 경로는 미검증이다.** 검증 환경의 탭이 `document.hidden = true`라
`requestAnimationFrame`·`requestVideoFrameCallback`이 발화하지 않아, 적재·조회·오디오만
타이머로 우회 검증했다. 보이는 창에서의 부드러움은 사람이 직접 봐야 한다.

## 알려진 한계 (01단계에서 해결)

캔버스로 다시 그리므로 **전체화면·자막·화질설정·재생컨트롤이 동작하지 않고**,
해상도가 640×360으로 고정된다. 시크·일시정지·배속은 대응하지 않는다.
이는 README 위험 표 첫 줄(「지연 재생 시청 품질」)이 말하는 그 문제이고,
M1의 정량 기준(720p 무드롭 60초)이 이 PoC가 아니라 01단계 구현을 겨눈 이유다.

메모리는 640×360 × 70슬롯 ≈ 61.5MB다. 1080p로 올리면 300MB를 넘어 PoC 범위를 벗어난다.

## 탐지 규칙에 대해

`DETECT` 경로는 "직전 1초가 조용했고 지금 RMS가 급등"이라는 **조악한 규칙**이다.
02단계의 규칙 기반 탐지기(정적 → 음량 급등 + 저음 럼블)를 대신하지 않는다.
제안서에서 "지연 버퍼가 있으면 도달 전 개입이 가능하다"를 보이는 용도로만 쓴다.
임계값(`median < 0.02`, `cur > median * 5`)은 영상마다 다시 맞춰야 한다.
