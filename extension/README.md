# scareblock 크롬 확장 (01단계)

M1을 위한 MV3 뼈대. **탐지는 아직 가짜다** — 계약대로 넘기면 도달 전에
가려지는지를 확인하는 것이 M1의 목적이다.

## 설치

1. `chrome://extensions` 접속
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 이 `extension/` 폴더 선택
4. 유튜브 영상 페이지(`/watch`)로 이동

영상이 3초 늦게 재생되고, **10초마다 가짜 트리거**가 나서 블러가 걸린다.
콘솔에 `가짜 트리거 ... → 3s 뒤 도달 전 블러` 가 찍히고, 실제 블러는
그 3초 뒤에 나타난다. **그 간격이 이 시스템의 존재 이유다.**

## 콘솔

```js
scareblock.stats()      // 계측값 + M1 판정
scareblock.blurNow()    // 지금 장면을 도달 전에 가린다
scareblock.stop()       // 원복
```

## M1 판정

`stats()`의 `M1통과`는 **`연속무드롭초 ≥ 60`** 일 때 `true`다.

`연속무드롭초`는 마지막 끊김·디코더드롭 이후 흐른 시간이다.
M1 기준이 *"60초 이상 유지"* 이므로 **누적 0이 아니라 연속 60초**가 맞다.
누적으로 재면 오래 돌릴수록 통과가 불가능해진다 — 10분 돌리면 그 안에
한 번만 끊겨도 실패로 잡힌다.

누적값과 `끊김_분당` · `누락_초당` 비율도 함께 낸다. 길이가 다른 측정을
비교하려면 비율이 필요하다.

**`적재누락`은 판정에 넣지 않는다. 사용자가 느끼지 못하는 내부 샘플링 손실**이기
때문이다. (한때 「해상도·캡처율과 무관한 상수라 통제 불가」로 설명했으나 틀렸다 —
프레임마다 부르던 `getVideoPlaybackQuality()`가 원인이었고, 4Hz로 낮추자 초당
18.8에서 0.1로 줄었다.) 근거는 [`poc/README.md`](../poc/README.md).

## 구조

| 파일 | 역할 |
|---|---|
| `config.js` | 상수. 값의 근거는 `poc/README.md` |
| `ringbuffer.js` | 프레임 링버퍼. 조회는 이분 탐색 O(log n) |
| `player.js` | 지연 재생·블러·음량 페이드다운. **계약 소비자** |
| `detector-fake.js` | 가짜 트리거. **계약 생산자** — 02단계에 교체된다 |
| `main.js` | 조립 + 유튜브 SPA 네비게이션 대응 |

**재생기와 탐지기는 배열 하나로만 만난다.**

```js
[{ time: 13.42, category: "jumpscare", confidence: 0.87, duration: 1.2, source: "rule" }]
```

`time`은 **라이브 mediaTime**이다. 화면은 그보다 `DELAY_SEC` 뒤를 보여주므로,
표시 시각이 그 구간에 들어올 때 블러가 걸린다.

## 설정값

`config.js`의 기본은 **1280×720 @ 40fps**(130슬롯 ≈ 457 MB)다.
**60fps 캡처도 가능하다** — 오버헤드를 걷어낸 뒤 rVFC는 60fps로 돈다. 그럼에도 40으로 두는
이유는 메모리뿐이다(190슬롯 ≈ 668 MB). 01단계 메모리 실측 뒤에 다시 판단하는 열어둔 선택지다.
측정 근거는 [`poc/README.md`](../poc/README.md) 「720p 자원 측정」.

## 오디오 재동기화

화면은 **mediaTime** 기준으로 `DELAY_SEC` 뒤를 보여주는데 `DelayNode`는 **벽시계**로
지연한다. 정상 재생에서는 둘이 같지만 세 곳에서 어긋난다. 뿌리가 하나라 한 곳에서 받는다.

| 상황 | 그냥 두면 | 처리 |
|---|---|---|
| **일시정지** | 멈춘 뒤에도 소리가 3초 더 난다 | `AudioContext.suspend()` — 지연선 내용이 보존된다 |
| **배속** | 2배속에서 소리가 1.5초 먼저 난다 | `delayTime = DELAY_SEC / rate` (50 ms 램프) |
| **탭 숨김** | 돌아오면 과거 화면이 뜬다 | 링버퍼를 비운다 (시크와 같게) |

**일시정지에서 지연선을 버리면 안 된다.** 그 안에 든 3초는 **화면이 앞으로 보여줄
구간의 소리**다. 아직 한 번도 나간 적이 없다. 버리면 재개 후 3초가 무음이 된다.
그래서 드레인도 폐기도 아닌 **정지**가 답이다.

**탭 숨김은 반대다.** rAF·rVFC가 멈춰 링버퍼만 비는데 영상과 오디오는 계속 간다.
돌아왔을 때 버퍼에 남은 건 낡은 프레임뿐이라 그대로 쓰면 과거 화면을 띄운다.
비우고 3초간 검은 화면으로 다시 채운다 — **검은 화면이 가장 안전한 상태**다.

## 알려진 한계 (01단계에서 남은 것)

- **전체화면·자막·화질설정이 동작하지 않는다** — 캔버스로 다시 그리기 때문
- **광고 미대응** — 광고 중에는 `<video>`가 광고라 링버퍼에 광고 프레임이 쌓인다.
  `#movie_player`의 `ad-showing` 클래스로 감지해 지연을 잠시 끄는 가드를 넣을 수 있다
- 재생 중 화질 자동 전환 시 화면이 한 번 튈 수 있다 (확인 안 됨)
- MV3 `world: "MAIN"`이라 `chrome.*` API를 못 쓴다.
  04단계 설정 UI에는 ISOLATED 콘텐츠 스크립트와 `postMessage` 다리가 필요하다
