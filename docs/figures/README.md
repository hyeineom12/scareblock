# 논문 그림

정보처리학회 추계학술대회 원고(#15)용. **분량이 2페이지라 그림은 하나뿐이다.**

## `delay-budget.svg` — 지연 예산 타임라인

논문의 기여 ①「개입을 위해 없던 지연을 의도적으로 도입한 설계 결정」을 그린다.

| 패널 | 내용 |
|---|---|
| (a) `L = 0` | onset과 사용자 노출이 같은 시각이라 탐지 확신이 노출보다 늦다. 예산이 음수다 |
| (b) `L = 3.0 s` | 라이브 축과 화면 축을 3초 띄우면 그 사이가 개입 준비 예산이 된다 (≈ 2.98 s) |

### 축척 — 바뀌는 곳은 한 군데뿐이다

**(a)와 (b)의 본 축은 같은 축척이다: 75 단위 / 초.** 이 축척에서 25 ms 분석 창은 1.875 단위라
사실상 보이지 않는다. **보이지 않는다는 것이 (a)의 요점이고 그래도 치명적이라는 것이 결론이라,**
과장해서 키우지 않고 아래 확대 상자로 따로 그린다.

| 곳 | 길이 | 뜻 |
|---|---|---|
| (b) onset 옆 음영 | 1.875 단위 | 25 ms, **실척** |
| (b) 예산 화살표 | 223.1 단위 | 2.975 s → 라벨 `≈ 2.98 s` |
| (a) 확대 상자 안 | 150 단위 | 25 ms, **×80** (150 / 1.875). 상자에 배율을 적었다 |

그림 어디에도 **표시 없는 과장은 두지 않는다.** 고치면 이 표의 숫자를 다시 맞춘다.

### 값의 출처

| 값 | 출처 |
|---|---|
| `25 ms` 분석 창 | `eval/features.py` `WIN_S = 0.025` |
| `3.0 s` 지연 | `extension/src/config.js` `DELAY_SEC = 3.0` (PR #23) |
| 처리 시간 | **미측정.** 확대 상자에 「+ 처리 시간은 미측정」으로만 적었다 |
| 블러 렌더링 시간 | **미측정.** `eval/evaluate.py` `RENDER_S = 0.0` — 그림에 넣지 않았다 |

### 캡션 — 정의상 성립하는 것과 측정할 것을 가른다

(a)의 「노출보다 늦다」는 확신 시각을 **분석 창의 끝으로 정의했기 때문에 정의상 성립한다.**
설계를 보여주는 그림으로는 정확하지만 **측정 결과처럼 쓰면 동어반복으로 반박당한다.**
예산 2.98 s도 분석 창만 뺀 상한이라 처리·렌더링 시간만큼 줄어든다. 그래서 캡션은 이렇게 쓴다.

> **그림 1.** 지연 예산 타임라인. (a) 지연이 없으면 탐지기가 확신하는 시각(분석 창의 끝)이
> 사용자 노출보다 늦어 개입할 수 없다. (b) 3초 지연을 도입하면 탐지와 노출 사이에 개입 준비
> 예산이 생긴다. 예산 2.98초는 분석 창(25 ms)만 뺀 상한이며 처리·렌더링 시간은 아직 측정하지
> 않았다.

### 크기와 형식

**1단 폭(KIPS 2단 기준 약 82 mm)에 맞춰 짰다.** `viewBox` 가로 380이 82 mm이므로 1 단위는
0.216 mm고, 본문 글자(`font-size` 9.5 ~ 12.5)는 **5.8 ~ 7.6 pt**가 된다. 가로를 늘리면 이 값이
같이 커지니 원고에서 크기를 바꿀 때 다시 계산한다.

`delay-budget.png`는 **같은 SVG를 968 × 871 px로 래스터한 것(82 mm 기준 300 dpi)**이다.
KIPS 최종 제출이 한글·워드·PDF라 SVG가 그대로 안 들어갈 수 있고, `Noto Sans KR`이 없는
환경에서 폰트가 바뀌므로 **원고에는 PNG를 넣는다.** SVG가 원본이니 고치면 PNG를 다시 뽑는다.
